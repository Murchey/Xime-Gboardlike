# 智能纠错测试报告

> 测试日期：2026-11-07　设备：GM4XIV8TGABUTOPJ（Android 13）　方案：白霜拼音（rime_frost）
> 目的：确认「Xime 原版」与「Gboard 仿版」两种纠错引擎是否真的有用，并决定是否还需要“实验性”与警告标注。

## 一、结论（先看这里）

1. **两个引擎都能工作**：输入一个“错一个键”的拼音（`nihap`，本意 `nihao`），候选栏出现带「纠错*」标记的「你好」「拟好」。
2. **测试前它们其实一度完全失效**：自定义补丁被第二个 `patch:` 块覆盖，纠错组件根本没有被加载（见第四节问题 1）。修复后恢复。
3. **“实验性”标注可以去掉**：功能链路已验证可用；但“猜测性质、只追加不替换”的提示值得保留，已改成更准确的一句话。
4. **两个引擎的差异**：本次用例里 Gboard 仿版多给出 2 个纠错候选（4 个 vs 2 个），首选一致；样本有限，不代表普遍规律。

## 二、这两个引擎在做什么（通俗版）

你在手机上打字，手指落在键的中心附近，但很少“正好在正中心”。

- **Xime 原版**：记录你每个键实际按偏了多少（上下左右），再用一个小神经网络判断“这次按偏，有多大概率是本来想按旁边那个键”。它更保守。
- **Gboard 仿版**：把每个键当成一个“中间准、四周逐渐不准”的热区（高斯热区），同时比较“按下的键”和“附近键”哪个更像你想按的，再交给解码器一起判断。它对“整只手偏了半格”更敏感。

两者都会把结果**追加在正常候选后面**，并用「纠错*」标出来；不会自动替换你要打的字。

## 三、测试方法

1. 启用「智能纠错」，选择引擎。
2. 切换到**全拼方案**（白霜拼音）。注意：纠错只对“按键字母 = 编码”的方案生效；九键不参与，双拼/雾凇这类若字母能直接对齐也可参与。
3. 在笔记里逐个点按键盘输入 `n i h a p`（故意把 `o` 按成相邻的 `p`）。
4. 观察候选栏是否出现带「纠错*」的候选，并读取日志：
   - `CorrectionTranslator: HIT input=nihap gain=16 produced=N` 表示纠错命中，产出 N 个候选；
   - `miss …` 表示评估过但没有足够把握，不出纠错候选。
5. 两种引擎各重复一次。

## 四、测试结果

| 引擎 | 日志（关键行） | 候选栏（前 3 个） | 结论 |
|---|---|---|---|
| Xime 原版 | `HIT input=nihap gain=16 produced=2` | 你好「纠错*」、拟好「纠错*」 | 命中，纠错候选排在正常候选之后 |
| Gboard 仿版 | `HIT input=nihap gain=16 produced=4` | 你好「纠错*」、拟好「纠错*」、你还「纠错*」 | 命中，候选更多，首选相同 |
| 对照（修复前） | `selfCheck … => correction=false` | 无「纠错*」候选 | 纠错组件未加载，两个引擎都不生效 |

### 发现的问题

**问题 1（已修复）：补丁被覆盖，纠错整体失效。**

`<方案>.custom.yaml` 里同时存在两个 `patch:` 块时，YAML 同名键以后者为准，前一个块被静默丢弃。实测文件：

```yaml
patch:
  "engine/translators/@before 0": correction_translator
  ...
patch:
  'grammar/language': 'XimeGboard'
  ...
```

第二个块是语法参数保存时追加的；文件开头的 BOM 让旧逻辑没识别出已有 `patch:`，于是又写了一个。
修复：`GramPatch` 写入前合并重复的 `patch:` 块（并去掉 BOM），新增单测覆盖该场景。
修复后 `rime_frost.custom.yaml` 只剩一个 `patch:`，重启自检 `correction=true`，纠错恢复。

**问题 2（已修复）：引擎选择在冷启动后丢失。**

设置页选择引擎只改了运行时状态，进程重启后回落到「Xime 原版」。现在应用启动时会读取已保存的引擎选择。

**问题 3（记录待查）：简体拼音没有被注入纠错组件。**

`pinyin_simp.custom.yaml` 没有纠错补丁，`selfCheck` 显示 `correction=false`。原生侧注入前会查找方案的主词典，找不到就跳过；具体是词典名解析问题还是该方案结构差异，尚未确认。雾凇/白霜/双拼/笔画等方案正常。

## 五、标注调整

| 位置 | 调整前 | 调整后 |
|---|---|---|
| 设置入口标题 | 智能纠错（实验性） | **智能纠错** |
| 说明 1 | ⚠️⚠️⚠️警告1：此功能实验性质，只对默认布局、开发者自己使用习惯做了训练，不承诺所有用户可用。 | 纠错是基于按键落点做的推测，偶尔会猜错；它只追加候选、不会自动替换，点选前请确认。 |
| 说明 2 | ⚠️⚠️⚠️警告2：不支持任何自定义按键布局的键位纠错。 | 使用自定义按键布局时，键位几何与默认布局不同，纠错可能不生效。 |

理由：功能已验证可用，“实验性质/不承诺可用”已不准确；但“会猜错、不自动替换”仍是对用户有意义的提醒。

## 六、如何自己复现

1. 设置 → 智能纠错 → 打开开关，任选一个引擎；
2. 切到白霜拼音（或其他全拼方案）；
3. 输入 `nihap`；
4. 看候选栏是否出现「纠错*」；
5. 若想看内部日志：设置 → 关于 → 日志，搜索 `CorrectionTranslator`。

## 七、术语表

- **纠错候选**：系统猜“你可能想打另一个词”，追加在候选栏后面的词，带「纠错*」标记。
- **邻键**：一个键上下左右相邻的键，例如 `o` 的邻键是 `i`、`p`、`k`、`l`。
- **信道模型**：把“按键落点”翻译成“本来想按哪个键”的统计模型。
- **高斯热区**：以键中心为最高点、向四周衰减的“命中概率”分布。
- **selfCheck**：应用启动时自检“当前方案里是否真的加载了纠错组件”，结果写入日志。
