# XimeGboard 全拼／双拼整句滑动输入计划书

> 参考：D:/Projects/vibecoding/GboardApk（Gboard 18.4.1 beta 静态分析资料）
> 状态：计划书已批准；本轮只交付文档，不改功能代码、不构建、不安装、不提交。

## 目标与已确认的交互

- 首版支持 26 键中文全拼和双拼的**整句连续滑动**。句子由字词组合产生，不要求整句预先存在于短语库。
- 抬手后进入候选栏，点候选、空格或回车明确确认后才上屏，不自动提交首选。
- **只保留直接滑动输入，不要左右滑光标**：移除本次 26 键中文输入区的整区横滑光标接管，也不迁移到空格。光标通过输入框、编码区点选或编辑面板定位。
- 功能默认关闭；开启后字母区拖动归滑动输入，保留点按和长按，原字母滑动快捷动作暂不触发。关闭功能后恢复这些快捷动作，横滑光标不作为替代交互。
- 全程离线，不上传输入内容或轨迹。

"整句"保证完整的音节、分词、字词组合和候选确认能力，不承诺所有模糊轨迹、词典外字符或无限长度都能百分之百识别。

## 二、使用流程与边界行为

| 操作 | 行为 |
| --- | --- |
| 点按字母 | 保持普通输入 |
| 从字母开始跨键连续滑动 | 显示轨迹，不逐键发字符 |
| 中途停顿、回摆或绕圈 | 作为分词、重复键等识别特征，不自动上屏 |
| 抬手 | 显示整句候选和可编辑编码 |
| 确认候选／空格／回车 | 整句只提交一次；待确认时回车先确认，不顺带发送 |
| 再滑一段 | 追加未确认编码，重算整句，不提前提交上一段 |
| 点按字母、退格、点选编码光标 | 编辑编码，取消旧计算并重算受影响部分 |
| 点标点 | 作为待确认句子的附加内容，不偷偷提交首选 |
| 取消本次滑动 | 恢复滑动前可编辑组合 |
| 换宿主、换方案、部署、布局变化或系统取消 | 取消过期轨迹，不把旧结果写入新输入框 |

首版允许从空闲或尚未选定句段的编码状态开始。已有分段确认状态时，不用一次替换原码破坏其结构，需先结束当前分段；普通 Rime 输入仍可继续。

## 三、触摸与轨迹层

### 独立物理键位快照

新增滑动几何注册表，每个实例保存：物理 ID、逻辑编码、真实 tap 绑定、键盘分区、局部矩形和角色。允许一个字母对应多个物理键。

不使用显示文字、韵母提示或静态 QWERTY 坐标代替编码和几何。所有触点统一到键盘局部像素坐标；悬浮布局不能重复乘缩放比例。

DOWN 冻结 schema 与 geometry 版本；旋转、尺寸、布局配置、分体或位置发生变化即取消本次轨迹。

### 统一手势仲裁

状态：Pending → Tap／LongPress／Glide → Finished／Cancelled。

- Pending 只做按压反馈和采样，不提前执行字符或符号动作。
- 有效字母起点、超过抖动范围并形成跨键运动后由 Glide 独占。
- 普通键、横屏紧凑键、父容器全部读取同一所有权；取消长按定时、方向动作和取消补点击，避免幽灵字符。
- 第二根手指加入时取消滑动且不补字，始终按 pointerId 跟踪。
- 去掉本次 26 键中文区域的整区横滑光标。空格保留点按、长按等原功能，左右拖动不移动光标。

### 采样与绘制

保留坐标、时间和历史点；原始轨迹与解码点分开保存。处理噪声、弧长重采样、转角、驻留、重复进入及回环；不能仅把经过的键去重成字符串。

轨迹在独立 Canvas 层按帧绘制，解码在后台执行，不让每个触点触发整张键盘重组。轨迹颜色适配主题，抬手后短暂淡出，视觉参数自行设计并真机调整。

## 四、全拼与双拼方案适配

使用当前已部署的 dictionary、packs、prism、alphabet、合并后的 speller/algebra。

- 复用 Rime 原生 Projection／Script 生成音节 ID 到合法键串及属性的索引，并用真实 Prism 校验。
- 不硬编码方案名称，不用 Kotlin 正则重写双拼，也不从 preedit_format 或键面提示反推编码。
- 保留零声母、模糊音、多音字、派生规则和多编码路径，不假设所有双拼音节机械地等于两个字母。
- 词表包括主表与 packs；用户词按原始音节图匹配，不能直接把双拼键串当作 userdb 词键。
- 验收覆盖普通／雾凇全拼，以及自然码、小鹤、微软、搜狗、紫光、ABC、加加双拼，并加入万象或自定义 patch 样本。
- 缺编译资源、无法用当前键盘表达的编码或纯状态式 Lua 转换应给能力检查结果，不能静默改用另一套方案。

**分号韵母键**：空闲 Shift 不变；本次滑动形成首个有效编码并进入韵母阶段后，相关方案的 Shift 位置显示并参与分号输入，不能等抬手才建立这一角色。复用固定物理矩形，支持分体左右实例；小鹤等方案不变。

## 五、整句解码架构

链路：真实几何 → 轨迹特征 → 拼写／音节格 → 字词图与整句联合搜索 → Rime 复核 → 候选确认。

### 第一层：轨迹到合法拼写格

原生解码器综合邻键空间似然、起终点、方向、转角、停留、跳过键和重复键代价，保留多条合法编码与音节路径。全拼使用音节前缀约束，双拼使用实际方案键串约束。

### 第二层：贯穿整条轨迹的整句搜索

Beam 状态包含轨迹进度、拼写节点、音节位置、词典前缀、词边界、上下文、累计分数和回溯指针。

- 空间、合法拼写、静态／用户词频和上下文共同参与剪枝。
- 分词由搜索决定；词边界后继续同一条轨迹，无须抬手。
- 同时保留多音、不同切分和不同编码，不能先固定最近键串再查一次词典。
- 未命中整词时使用合法单字路径组成新句子。
- 复用 WordGraph／Poet 的可用部分，并新增把空间分并入搜索的适配。Grammar 存在时利用它，否则明确采用词频与边界代价回退，不宣称所有方案都有强语言模型。
- 长句用流式推进和检查点，不在每个 MOVE 重算全前缀。超资源预算时明确提示并保留原组合，不能静默丢尾或降成逐词确认。

## 六、Rime 与候选确认

### 有界旁路复核

新增滑动批量查询接口，复制主会话相关 schema 选项并带部署、词表、用户词和布局版本。

轨迹计算、静态索引和搜索在引擎锁外完成；仅对少量完整假设做限时批量复核。不能逐采样或逐 beam 调用 bypassLookup，也不能因为旁路 session 独立就绕过 Rime 并发约束。

接口明确区分 Busy、NoCandidate、Unsupported、Cancelled 和 Error；返回完整消费范围、分段及来源。不同编码查询的候选排名不能直接当成可比较概率。

部署前先取消任务、释放资源租约，再维护，防止旧 Table／Prism 和词图指针悬挂。

### 组合会话与提交

新增 GlideCompositionSession，保存轨迹 ID、revision、宿主 token、方案／布局指纹、原码、多路径候选和编码／音节／词／轨迹对齐。

候选新增明确的滑动来源引用，不混用其他 session 索引，不套用插件直接文本提交。抬手建立未确认的可编辑组合；确认时重验并通过原生候选桥接进入正常 Rime 选词、学习与提交路径。

原型必须证明：未确认不提交；确认只上屏和学习一次；备选编码能正确确认；失败／取消可恢复原组合。现有 API 不足时补受控桥接，不能用直接 commitText 猜测汉字掩盖问题。

字母编辑、退格与编码点选递增 revision，旧结果丢弃并重算后缀。候选变换和简繁转换保留原始来源，显示与实际提交一致。

## 八、实施阶段

1. **能力与提交原型**：先验证真实方案、多词新句、完整消费、旁路选项同步、确认学习、恢复及部署失效。
2. **触摸与轨迹**：统一所有权、实际几何、普通／紧凑组件、分体和分号，不补字、不误触发符号或光标。
3. **整句联合解码**：拼写格、字词图、长轨迹检查点、用户词和 Rime 批量复核。
4. **编辑与候选闭环**：追加轨迹、退格／点选编码、标点待确认、取消、过期结果保护。
5. **准确率与性能验收**：固定评测集再调参，原生／JVM／Compose 测试、构建及真机闭环。

这些是内部推进阶段，不把仅识别几个词的中间原型当作首版完成。

## 九、验收标准

功能覆盖：全拼与各双拼、patch／packs／用户词、整句组合、多音和重复码、分号 ing、不同分词；分体重复键、悬浮、隐藏标签、自定义布局；点按／长按／多指／取消；不误移光标；抬手未上屏；确认一次；退格和点选编辑有效；旧任务不覆盖新输入；部署不访问失效资源。

合成轨迹用于确定性回归，不能单独证明识别率。真实评测至少 3 位使用者、每人 50 句、全拼和双拼合计不少于 300 条；调参与验收按句子／使用者隔离，包含未见整句和长句，明确同意后采集，默认不记录日常输入。

拟定工程目标（不是 Gboard 公开指标或已达成结果）：

- 8–20 字常见句：首选整句命中率 ≥ 80%，前五整句命中率 ≥ 95%。
- 21–40 字长句单独统计，前五整句命中率目标 ≥ 85%，同时报告字符错误率，不能混入短词稀释。
- 抬手至最终候选 P95：8–20 字 ≤ 250ms，21–40 字 ≤ 500ms。
- 60Hz 设备按 16.7ms 帧预算检查轨迹绘制；解码不在主线程；引擎短锁预算与普通按键降级率必须测量。
- 功能新增常驻内存目标 ≤ 64MB；复用只读词表，不复制多份巨型词库。

未达标继续改进整句搜索，不改成"只支持常用词"；能力确有阻断时明确报告，再由你决定范围。

## 十、本轮结论

方案方向固定为：**整句全拼／双拼、直接滑动、抬手候选确认、没有左右滑光标**。

最大难点是长轨迹的多路径搜索、Rime 候选与学习桥接，以及真正独占的手势仲裁，轨迹动画只是小部分。现有代码能提供基础，但尚不能承诺达到 Gboard 识别率。
